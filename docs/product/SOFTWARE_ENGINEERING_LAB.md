# Software Engineering Lab

Status: ACCEPTED product concept; implementation details PROVISIONAL
Traceability: US-004; future US-010 refinement candidate

## Purpose

The Software Engineering Lab is HomeLab's first flagship professional area. It demonstrates Senior Software Engineering through inspectable systems, evidence, and decisions—not a technology inventory.

## Capability model

Public presentation must be backed by verified, publishable evidence.

- **Core direction:** .NET, C#, Azure, Cloud, SQL Server, PostgreSQL, React, TypeScript.
- **Production Experience:** only technologies with verified production evidence.
- **Active Exploration:** current growth areas; Python belongs here unless verified evidence supports another classification.
- **UNKNOWN/UNVERIFIED:** not publicly asserted as expertise.

The listed core direction is product intent, not proof of specific companies, tenure, metrics, or outcomes.

## Planned stations

| Station | Visitor value | Required evidence |
|---|---|---|
| Architecture Table | Understand a system and message flow | Diagram, decisions, labeled simulation |
| Engineering Decisions Wall | See trade-offs and judgment | Verified context or explicitly generic case study |
| Technology Wall | Scan capability level quickly | Evidence-backed classification, no logo soup |
| Current Workbench | See current experiments | Dated, clearly marked status |
| Flagship Projects | Inspect credible outcomes | Publishable project records and claim provenance |

## Architecture simulation concept

A future accepted story may implement `API → QUEUE → WORKER → DATABASE`, with CACHE where justified. `SIMULATE FAILURE` may show service failure, queue growth, retry, circuit breaker, latency, errors, recovery, and recovery time.

All generated values and scenarios must be prominently labeled `SIMULATION`. The experience must explain engineering meaning, not merely animate nodes. A semantic equivalent must expose the topology, event sequence, and decisions.

## Content and security constraints

- No permanent hardcoded professional truth.
- Public claims originate from the safe Portfolio Knowledge projection.
- Missing content renders as UNKNOWN or is omitted; it is never invented.
- Zavit may use only public portfolio knowledge.
- Technology prominence must reflect evidence, not visual convenience.

## Future acceptance themes

- Recruiters identify senior engineering focus and core stack quickly.
- Engineers can inspect at least one meaningful trade-off and failure/recovery sequence.
- Every professional claim is traceable to publishable evidence.
- All essential station content is keyboard accessible and available outside WebGL.
- Runtime meets the accepted performance budget on target profiles.

This foundation does not implement the lab or simulation.
